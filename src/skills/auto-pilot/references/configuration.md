# Configuration defaults — full rationale

`/auto-pilot` reads `.gitissue.yml` once at start (never re-read per iteration).
The canonical schema lives in `docs/config-schema.md`; this file expands the
per-key rationale behind each `autopilot.*` default. The SKILL.md body carries
the bare default values — read this when you need the *why* or the edge-case
behavior.

- `autopilot.mode: balanced` — merge mode. See **Merge Modes** in SKILL.md for the three values.
- `autopilot.merge_partial: false` — never merge a PR with unresolved fixable review issues unless explicitly opted in. Only honored when `mode: aggressive`.
- `autopilot.max_iterations: 10` — maximum issues to process before stopping.
- `autopilot.max_parallel: 1` — maximum resolver lanes in one bounded fan-out (`1..8`). The scheduler uses only members of one persisted `summary.parallel_groups` entry after applying the ordinary eligibility checks, so file-independent issues overlap while dependency order remains intact. Concurrency ends at resolver fan-in: PR review, every merge gate and merge, run-log append, run-state checkpoint, triage-cache update, and worktree cleanup remain serialized. The main agent creates and owns every parallel worktree; setup failure fails only that lane and **never falls back in-place**, because two lanes sharing the original index would defeat isolation. A value of `1` bypasses every new batch/worktree/lane-state branch and follows the legacy in-place sequence exactly.
- `autopilot.review_cycles: 3` — maximum fix attempts per PR. After this many cycles, if issues remain the behavior depends on `autopilot.mode` (see *Merge Modes*). Reduced from 10 — the script pre-pass in issue-pr-review handles lint/format, so 3 LLM cycles suffice for logic issues. A cycle = one fix attempt + one review pass. Confirmation-only review passes (spawned after a PASS to verify, without a preceding fix) do not consume a cycle.
- `autopilot.auto_merge: true` — **legacy** field, retained for backwards compatibility; it is ignored whenever `autopilot.mode` is set. How it resolves otherwise is stated once in the *Resolution rules* under *Merge Modes* in SKILL.md.
- `autopilot.pause_on_failure: false` — skip failed issues and continue to the next one (autonomous default). When false, the auto-pilot logs the failure, adds the issue to the skip list, and moves on. Set to true only if you want the loop to halt on every failure for manual inspection.
- `autopilot.skip_labels: ["wontfix", "blocked", "do-not-merge"]` — skip issues with these labels.
- `autopilot.critical_labels: ["critical", "priority:critical"]` — labels that mark an issue as critical. When a critical issue has unresolved review problems after all cycles, the loop stops and asks the user for a decision instead of auto-creating a follow-up.
- `autopilot.respect_dependencies: true` — honor `Depends on #N` / `Blocked by #N` markers in issue bodies. Before merging PR-A, verify that every dependency referenced from issue A is closed and its PR merged; if not, do not merge — print a structured alert, record `blocked_by_dependency`, leave PR-A open, and continue to the next eligible issue (the run is not paused). Set to `false` to skip the gate entirely. See *Phase 5 — Merge* in `references/phases/phase-5-merge.md` for the full check.
- `autopilot.triage_cache_max_age_minutes: 60` — how old `.gitissue/triage.json` may be and still be reused by *Step 1.1a*'s cache gate. Age is only half the test: the gate also requires that no commit landed after the cache's own `updated` timestamp, so a cache written a minute ago is still `stale` once a merge lands. Set `0` to refuse any pre-existing cache, so the run always starts with a full triage — matching `docs/config-schema.md`'s "`0` disables reuse". It is **not** a per-iteration off-switch: *Step 1.1a* is evaluated once, before the first iteration, so `0` forces the full triage on iteration 1 and nothing after it. `retriage_every: 1` is the key that forces a full triage every iteration. The gate fail-safes to `stale` on any doubt, so a wrong value costs a re-triage and never a wrong pick.
- `autopilot.retriage_every: 0` — force a full re-triage every N-th iteration, counted from the 1-based `{i}` at the top of the loop (`i % N == 0`); `0` (default) never forces one. The check is **not** gated on a merge, so `N: 1` forces a full triage every iteration — including under `mode: conservative` and on iterations that leave a PR open. *Step 1.6*'s incremental update is removal-only, so it stays correct as long as the backlog only shrinks; set this on long unattended runs against a repo other people file into, where new issues would otherwise not be seen until a pick miss. A pick miss forces a re-triage regardless of this value, and *Step 1.1b*'s live open-issue read is what makes that miss reachable on a reuse iteration — a newly filed issue is in that set and not in the cached order, which is the drift the retry recovers from.
- `autopilot.quarantine_after: 3` — how many **consecutive** `failed` runs an issue may have before *Phase 2.3* quarantines it. `0` disables the check outright: the script is never invoked and no label is ever applied. Three is chosen to be past the noise: one failure is often a flaky test or a transient API error, two can still be the same transient cause, and by the third the issue is reliably costing a full resolve-plus-review every run for nothing. The count is *consecutive* and derived by scanning `.gitissue/runs.jsonl` backwards to the issue's first non-`failed` record, so a single success anywhere in between resets it — an issue that was fixed and later regresses starts its streak over rather than inheriting an old one.
- `autopilot.quarantine_label: "auto-pilot-quarantined"` — the label *Phase 2.3* applies at the threshold. **SKILL.md's *Configuration* step appends it to the effective `skip_labels` set** as part of the same one-time load, which is the whole read side of the feature: the pick predicate already skips `skip_labels`, so there is no second gate to evaluate and no way for the two to disagree. The shipped default `skip_labels` does not contain the label, so this append is load-bearing, not tidy-up.

  **Why the label is the source of truth, and not a state file.** The requirement is "skipped until the label is removed", which only a durable, human-visible record can satisfy. A label lives on the issue: it survives a clone, a new machine, and `rm -rf .gitissue/`; a human can see why an issue stopped being picked and can clear it with one click. Every machine-local alternative fails one of those. A fourth file next to `run-state.json` / `run.lock` / `last-run-report.md` would add a second source of truth that can *disagree* with the label, and `run-state.json` could not hold it anyway — it is single-run and its key set is closed.

  **Why the counter fails open.** `runs.jsonl` is gitignored, best-effort, and deletable, so it can only ever be *progress toward* a quarantine, never the quarantine itself. When it is missing or unreadable the script still prints its line with `streak: 0` and exits 4, and the loop skips the check rather than guessing. The asymmetry is deliberate: a missed quarantine costs tokens on one more attempt, while a wrong quarantine silently parks a real issue that nobody is watching for. Losing the log therefore loses progress toward a quarantine and never an existing one — the label is untouched.
- `autopilot.max_runtime_minutes: 0` — wall-clock budget for the whole run, measured from the `started_at` in `.gitissue/run-state.json`; `0` (the default) is unbounded, preserving today's behavior for anyone who does not want a clock. Set it for a run under a CI job timeout, a nightly window, or a metered API budget. It is a **start gate, not a kill switch**: it is evaluated at the top of each iteration and around any rate-limit pause, because the orchestrator cannot interrupt a spawned subagent, so an iteration that begins inside the budget always finishes and no PR is abandoned mid-review. It also bounds a rate-limit pause — a `reset` that falls past the budget stops the run cleanly instead of sleeping through it. Expect an overshoot of at most one iteration; size the value accordingly.
- All `resolve.*` and `triage.*` settings are inherited by the sub-skills.
