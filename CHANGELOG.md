## [Unreleased]

### Features
- **skills:** ship `gi-triage-graph`, `gi-stack-detect`, and `gi-model-cache` (#253) — the third wave of Phase 2, mechanizing the work that was pure arithmetic or pure lookup executed by a language model. `gi-triage-graph.py` directs the scanner's undirected edges, detects and breaks cycles, topologically sorts with the documented tie-breaks, groups the independent sets, subtracts the dates behind staleness and buckets P1/P2/P3, emitting the `.gitissue/triage.json` payload byte-compatibly (a test parses the schema out of the reference document and compares, so the two cannot drift); `/auto-pilot` Phase 1 now calls the **same script** rather than the same algorithm reimplemented, which is how two consumers drift apart. `gi-stack-detect.py` runs `/init-gitissue`'s language, framework, test-runner and size tables; an unmatched field comes back `null` **and** is named in `unresolved`, which is the LLM fallback's only trigger — the script never guesses to avoid an empty field — and `file_count_source` says whether the count came from `git ls-files` or a filesystem walk rather than presenting two different measurements as one. `gi-model-cache.py` runs the model-data lifecycle (locate, seed under the *seed's own* date, prune, age against the TTL) and returns the resolved effort→two-model bands with each pick's own per-task cost, so the 12.3KB reference document is no longer read on every default run — it is now marked refresh- and debug-only. The detection tables take a `--rules` JSON file rather than a config section, since a table keyed by names like `@angular/core` cannot be expressed in the restricted YAML the build's parity check parses. **No `build.py` change was needed** — the #251 pipeline discovers a script by regex plus filesystem, which is the property this wave exercises. Untrusted input never reaches a command line: the scan arrives on **stdin**, dependency files and refreshed model data are read from disk, and a wave-3 call-site lint plus a static no-text-flag check pin that shape — every guard reverse-applied in a scratch copy and confirmed to fail. Each script fails **closed**: a corrupt model cache is exit 4, never silently reseeded from the bundle; an unparsable timestamp is exit 3, never treated as absent. Every replaced procedure survives as the documented fallback, and every call site classifies all four exit codes with exit 3 as a stop that no degrade path may swallow. The fourth script of this wave, `gi-dup-score`, was withdrawn from the change set before merge — the same double-counting defect recurred across four fix rounds and it needs a corrected scoring model rather than another patch; it remains tracked on #253. @luongnv89
- **skills:** ship `gi-secscan`, `gi-ci-wait`, `gi-issue`, and `gi-branch` (#252) — the second wave of deterministic scripts, replacing the four highest-frequency prose-executed procedures. `gi-secscan.py` is the pre-commit security gate as code: the same five rules as the canonical document (block on secret-bearing filenames and real API-key values, warn on large files, build artifacts, and protected branches), applied to `--staged` / `--working-tree` / `--range` / a stdin path list, printing one JSON verdict and **exiting 1 on a block**. That code is a verdict, not a runtime failure, and every call site says so explicitly — the default reading of a non-zero exit is "degrade", and degrading past a real secret is the one outcome the gate exists to prevent. Patterns extend per repository through a new `security.*` config section (`extra_secret_file_pattern`, `extra_secret_value_pattern`, `allow_pattern`, `max_file_size_mb`), which the script reads from `.gitissue.yml` itself. That is a security decision rather than a convenience: `.gitissue.yml` is repository-controlled and `/issue-pr-review` runs with a pull request's branch checked out, so any design where a caller interpolates a config *value* into the scan's command line would let a crafted value close its shell quoting and execute on the reviewer's machine at the moment the gate runs. No config value reaches a command line, and a test pins that. `gi-ci-wait.py` performs an entire CI wait inside one invocation and returns `pass`/`fail`/`pending`/`none`, replacing a poll loop that cost one agent tool call per poll; pending stays pending and an unmodeled check bucket counts as still-running, never as done. `gi-issue.py` serves repeat `gh issue view` reads from a short-lived `.gitissue/cache/` keyed by issue **and** field set, so a narrower cached read can never be served to a caller that asked for more; `--refresh`/`--invalidate` cover the read-after-write paths. `gi-branch.py` derives a branch name from an issue number, title, and type, and self-checks its output against the same grammar `idd-lint.py` enforces. Every replaced procedure survives as the documented fallback, and the pre-commit lint now accepts either the document or the script as the gate. The shared agents receive the scan path as a `{secscan_script}` spawn variable, since an emitted agent prompt cannot resolve a skill-relative path (issue #245). @luongnv89
- **build, skills:** add a scripts pipeline and ship `gi-config`, `gi-runlog`, `gi-deps` (#251) — `scripts/build.py` gains a third closure kind beside shared agents and runtime docs: a bare `shared/scripts/<name>.py` token in a skill's own files (or in a runtime doc reachable from them) resolves against the new `src/shared/scripts/` tree and is copied — byte-identical, `shutil.copy2` so the committed `0755` survives — into that skill's `references/scripts/`. Discovery is regex plus filesystem, so **adding a script needs no `build.py` change**; the token is directory-scoped because a bare `scripts/X.py` form collides with the prose mentions of this repo's own `scripts/` directory already inside the closure read set. Scripts are closure **leaves** (a `.py` comment can never drag a doc into a bundle), they render as absolute repo URLs inside agent prompts and are therefore not bundled when reachable only through an agent (issue #245), and a script may declare `# gi-requires: references/…` to make the build fail if a file it reads at run time is not bundled alongside it. Three scripts ship: `gi-config.py` *derives* the defaults from the bundled `config-schema.md` rather than restating them, validates `.gitissue.yml` against it, and prints the merged config as one JSON line — the six reader skills now load config with it instead of six prose copies of the same defaults; `gi-runlog.py` validates and normalizes one `runs.jsonl` record (5→3 `complexity` collapse, null-drop, `ts` fill, canonical key order) and either appends it or, with `--echo`, prints it and writes nothing — the machine form of the `--no-run-log` single-writer contract; `gi-deps.py` (the promoted `scripts/dependency_gate_parse.py`) parses local dependency issue numbers for the auto-pilot merge gate, which no longer cites a path that does not exist inside an installed skill. Every invocation keeps its prose fallback: a missing bundled file is fatal (the precheck list guarantees it shipped), while a runtime failure — no `python3`, a non-zero exit other than 3, unparsable stdout — prints a `⚠` line and follows the documented manual procedure. Shared exit codes are `0` ok, `2` usage, `3` invalid input (stop), `4` cannot complete (degrade). @luongnv89
- **resolver, review:** adapt effort to task complexity (#240) — `/issue-resolver` picks a pipeline **profile** (`light`/`full`) from the issue's pre-work `Effort` band before any subagent spawn, so trivial issues (XS/S) take a fast path (lighter Research, skipped 3-option Plan, skipped propose-skills, QA capped at 1 cycle) while complex or ambiguous work keeps the full pipeline; `/issue-pr-review` scales review depth from a diff-size/labels/linked-issue signal (fuller-of-disagreeing). The Decision Record + Acceptance Criteria table always emit, and the AC + traceability hard-blocks always run at full strength. The chosen profile is surfaced on the tracker line and in the `runs.jsonl` `profile` field. Opt out with `resolve.adaptive_effort: false` / `review.adaptive_depth: false` (both default `true`). Shared mechanism documented in `docs/agent-model-effort.md` (Complexity → pipeline profile). @luongnv89

### Fixes
- **ci, tests:** run every `tests/*.sh` in CI, and close the vacuity holes in the checks that guard it (#275) — 20 of 42 test files were invoked by no workflow at all, including the pre-commit security lint itself; each now has a named step in `.github/workflows/dist-check.yml`, split at the build so source-level checks fail fast and built-output checks run against a freshly verified `skills/`. A new T9 in `tests/test-build-script.sh` asserts the wiring, and a test may leave CI only through an `EXCLUDED` entry carrying a written reason. Both guards were then reverse-applied until they held. T9 decides "wired" against a **reduced** view of the workflows rather than their raw text: YAML comments are stripped — its own explanatory note in `dist-check.yml` named `tests/test-build-script.sh`, so deleting the test-build-script step left T9 green and the guard could not detect its own unwiring — and steps carrying `if: false` or `continue-on-error: true` are dropped whole, because a step that cannot run, or whose failure cannot fail the job, is not a gate. It also compares full repo-relative paths, so a correctly wired `tests/unit/x.sh` is no longer reported unwired by a basename match that cannot cross a `/`. The pre-commit security lint (`tests/test-pre-commit-security.sh`) stopped accepting a bare `references/scripts/gi-secscan.py` as a gate: that token is this repo's documented way of *citing* a shared script and already appears in prose that runs nothing, so a mention, a GitHub URL to the script, or a commented-out call each satisfied the gate while no scan ran — only a live interpreter command line gates now, and never one commented out. Its fence parser sees indented fences, tilde fences, fences longer than three backticks, and info strings (```` ```bash title="x" ````); `src/` holds 78 indented fences whose bodies used to leak into the prose window, where a scan command inside one could act as a false gate for a later, genuinely ungated `git push`. The adjacency window now counts physical lines, so an invocation separated from a commit block by an unrelated 60-line listing no longer gates it. Non-vacuity is pinned as the exact **set** of subject files instead of a count, which any two blocks satisfied. A second review round closed four more holes in those same guards. T9 split a step at a `- ` line of *any* indent, so a bullet inside a `run:` heredoc or a `with:` sequence detached a `continue-on-error: true` marker from the rest of its step — and because the split reset the marker, the remainder came back as a live step and a disabled test was reported as wired; a step now ends only at a `- ` line indented no deeper than its own, and `continue-on-error: TRUE` no longer slips past a case-sensitive match. The comment strip applied YAML's *plain-scalar* rule to block scalars, where `#` is literal, and deleted the invocation out of `run: |` bodies such as `echo "… #275" && bash tests/…` — a **false** CI failure on valid input, with a hint that named only causes that did not apply; stripping is now quote-aware, so a quoted `#` survives and a commented command still does not count. The security lint gained an `END` clause, because a fence left unclosed at end of file is valid CommonMark that renders normally and so was never evaluated at all — an ungated `git push` in the last fence of a file escaped silently. It also accepts an invocation from a preceding **shell** fence, which makes "scan in one block, push in the next" a gated pattern, and reads a leading `#` as the root prompt inside `console`/`shell-session` fences (only when the interpreter comes first, so a commented-out call still gates nothing). `docs/pre-commit-security.md` describes the lint that now exists — including the `python3`-only interpreter rule — and its *Lint Enforcement* section, which documents a contributor check no skill run can act on, is no longer bundled into the two skills that carry the document, restoring the bundled-doc byte headroom via issue #249's digest mechanism. A third round narrowed and repaired five of those same reductions. "A preceding fence" had been read as *any* fence, which handed the gate back to display-only text: a ```` ```text ```` transcript of the scan, a ```` ```markdown ```` template quoting the command, or a ```` ```json ```` payload carrying it as a string each gated an ungated `git push` below it — only prose and shell fences reach now, and the canonical document says so. `git -C <dir> push` is recognised as a subject, the form a worktree-based skill reaches for. On the T9 side an `EXCLUDED` entry written without its `|` returned the path as its own reason and quietly excused the test, so the written reason is mandatory in fact and not only in the comment above it; the comment strip reads `\"` inside a quoted run as an escape rather than a closing quote (it had truncated a `run:` body at the next `#` and failed a correctly-wired repo), re-cuts a line that ends still inside a quote by the quoting-blind rule (an apostrophe in a step name hid the comment behind it, and the commented-out invocation there counted as wiring), and reads `if: 'false'` as dead, which only the unquoted and double-quoted spellings were. Finally, `scripts/build.py` no longer aborts when a skill names a digest-dropped heading that another bundled document also uses: *Lint Enforcement* is a section of both `pre-commit-security.md` and `sync-conventions.md`, so citing the second aborted the build with a message about the first and two remedies that did not apply — such a heading is policed only where the citing file names the digested document too. @luongnv89
- **scripts:** give `gi-model-cache` a validation boundary, and close the `gi-triage-graph` and `gi-stack-detect` audit findings (#278) — `gi-model-cache` gains **one** validation boundary rather than scattered checks: every document — installed, cached, or seeded — is parsed with `parse_constant` refusing bare `NaN`/`Infinity` and then walked whole-tree, rejecting control and escape bytes (C0/C1, DEL, the Unicode line separators, the bidi overrides), over-long strings, and non-finite or negative numbers anywhere, keys included, under a 256 KB payload cap taken before the parse, a 64-level nesting cap, and a `RecursionError` guard — a payload nested a few hundred deep sits well inside the size cap, blows the parser's stack, and `RecursionError` is a `RuntimeError` rather than a `ValueError`, so it escaped as **exit 1**, a code no call site classifies. The unsafe-text class also now covers the characters that render as *nothing* — U+200B/200C/200D, LRM and RLM, U+061C, the word joiner and its invisible operators, and U+FEFF — which are worse than an escape sequence, not better: a model name that reads identically to a real one is the whole payload. All eight were accepted at exit 0 before. That path is persistent prompt injection — the cache re-enters on every later run with no refetch, and its strings render into the terminal *and* into created issue bodies `/auto-pilot` reads back. `data_version()` is a single backward scan instead of `([0-9]+(?:\.[0-9]+)*)\s*$`, whose nested quantification against a right anchor cost 3.8 s on a 32 KB `source` **on every run**; it is now 4 microseconds, verified equivalent to the pattern it replaced. The cache is written through `tempfile.mkstemp` (O_EXCL, 0600) with an explicit `0644` and `allow_nan=False`, closing a symlink-followable `target + ".tmp"`. `gi-stack-detect` no longer reports `file_count: 0` at exit 0 for a directory it could not read — `os.walk` swallowed every `OSError` and `isdir` succeeds on `chmod 000`, feeding `/init-gitissue` a confident `repo_size: small`; an unreadable directory at any depth is now exit 4, because a partial walk fabricates a size as confidently as an empty one. `gi-triage-graph` got its first independent audit: the precedence "blocking count" counted **incoming** edges too, so an issue blocked by three others outranked a peer that blocked nobody; a duplicated input edge voted twice and flipped the execution order for the same logical graph; `co_dependent` was emitted in input-edge order; and a structured value inside an edge escaped as exit 1, a code no call site classifies. All four are fixed, and 36 permutations of an all-ties graph now produce one identical summary. `gi-triage-graph`'s `parallel_groups` and `assign_priority` were audited too: every reported parallel group is genuinely independent — including against edges cycle-breaking removed, since a back edge always leaves a surviving path that separates its endpoints' levels (zero violations over 1200 cyclic graphs) — and all thirteen rows of the documented priority table agree, with the one row `detection.md` contradicts itself on (a stale bug that blocks nothing) resolved to P2 and the reasoning recorded where the next reader will hit it. The call-site injection lint closed five gaps found by adversarial mutation, each by removing what could be wrong rather than adding a case: `[name]` is a placeholder style, a command substitution counts wherever it sits (except the one that *contains* the call), every backtick span on a call line is inspected instead of the ones a heuristic admitted, the presence guard is a pinned **per-script count** rather than "at least one somewhere", and there is no `ROOTS` list any more — the lint walks every file the repository tracks. Twenty-seven adversarial mutants, 10 of which the old lint passed, are all caught. @luongnv89
- **security:** give `gi-secscan` an explicit byte-source contract, and close the `--range` net-diff and `verdict: none` merge holes (#272) — seven consecutive review rounds each found a *different* way to make the pre-commit gate return exit 0 with an empty `blocking[]` over a live key, and three of the seven were introduced by the previous round's own fix. Every one was the same bug wearing a new input: the scan read bytes that were not the bytes being shipped, then reported the path as scanned and clean. That class is now closed by construction rather than instance by instance. Each mode declares exactly one **byte source** per entry and reads that and nothing else: `--staged` and `--range` scan the blob **object id** from `git diff --cached --raw` / `git diff-tree --raw`, so no filename is involved in locating the bytes and no filename shape can redirect them; `--working-tree` scans the file on disk, with the path taken verbatim from `git status --porcelain -z -uall` and joined against a root derived from `git rev-parse --show-cdup` — a string that can only ever be a run of `../`, so the repository's own directory name never takes part in resolving a path. There is no fallback between sources: a declared byte source that cannot be read is **exit 4**, never a quiet retry against the working tree, which is exactly how a tidied copy came to be scanned in place of a blob. An unmerged index entry, a missing object, an unparsable `--raw` or porcelain record, and a file whose permissions deny the read all fail closed the same way; the last of those was an eighth silent pass, found while writing the contract. Caller-supplied lists keep their `unreadable-path` warning, since git makes no claim those paths exist. `--range` now walks `BASE..HEAD` commit by commit instead of diffing `BASE...HEAD`: a secret added and then removed *inside* the branch is absent from a net diff yet is still in the history `git push` sends. `tests/test-secscan-contract-272.sh` asserts the contract as a 3 × 15 mode × path-shape matrix — leading/trailing space, embedded newline, `\r`, an undecodable byte, `:`-prefixed and `0:`-alias names, quoted/octal git output, rename origin fields, untracked-directory collapse, a subdirectory cwd, a repo root ending in a space — where every cell compares a sha256 of the bytes the scan actually consumed (via the new diagnostic `--emit-sources`) against the bytes the mode ships, plus the exact path bytes. "Did not crash" is not an assertion anywhere in it, and a final phase reverse-applies each of the seven historical fixes to a scratch copy and **requires the matching cell to fail**, so the matrix cannot quietly stop testing anything. Two related gaps close with it: `gi-ci-wait` no longer returns a mergeable `none` from the first poll after a push — an empty check list is re-polled for `--none-grace` seconds and the new `none_confirmed` field distinguishes "this repo has no CI" from "the checks have not registered yet", with `/auto-pilot` and `/issue-pr-review` merging on `none` only when it is confirmed — and the `.gitissue.yml` search now stops at the top of the working tree, so a config in `$HOME` can no longer set `security.allow_pattern` for every repository beneath it (`gi-config`'s schema search is bounded at the same place, so the two cannot diverge). @luongnv89
- **skills:** fix disclosure gates and add checkable step completion criteria (#250) — five predictability gaps that let runs diverge or declare success with nothing to check. (1) `/issue-analysis` gated every-run-mandatory material behind "read that file when tuning/debugging", so the delegation payload and the Step 8-9 rendering/JSON spec could be skipped entirely; those pointers now read **read now**, and the 12.7KB no-Agent-tool procedure they shared a file with moved to its own `references/inline-fallback.md`, gated the other way — read **only** when the Agent tool is unavailable. `/issue-triage`'s `references/detection.md` pointer got the same inversion fix. (2) `/init-gitissue` reported `Config: ✓ generated` without ever reading the file back; it now re-parses the written `.gitissue.yml` as YAML, greps for surviving `{placeholder}` tokens, checks `platform` is present, and reports `DONE` only when all three hold (`PARTIAL` when no YAML parser exists, a rich error and stop on a real failure). (3) `/issue-resolver`, `/issue-pr-review`, `/auto-pilot` and `/issue-triage` now close every step with a **Step Completion Report** — `√`/`×` per check plus `Result: PASS | PARTIAL | FAIL` — with the format, the `PARTIAL`-vs-`FAIL` semantics and the per-step check names owned by each skill's own reference file (`report-templates.md` / `summary-format.md` / `output-and-persist.md`) so all seven built `SKILL.md` files stay under the 500-line cap. Checks are gates that could have failed, never restatements of a tracker metric, so the #165 de-duplication holds. `√`/`×` join `docs/terminal-style.md` as check glyphs distinct from the `✓`/`✗` status symbols. (4) `/issue-creator` no longer runs a mandatory stash-and-rebase before remote-only work: every write it performs goes out through `gh issue edit` or the GitHub contents API, so the sync protected nothing while being able to conflict-stop a pure create; the stash-first convention still applies, scoped to a run that actually writes the working tree. (5) The eight skill READMEs moved to the skill-creator standard `docs/README.md` and carry the AI-skip notice, with their doc references rewritten as absolute repo URLs so the relocated depth cannot dangle. @luongnv89
- **build, agents:** deliver the shared-agent conventions inside every injected subagent prompt (#245) — a spawned subagent's working directory is the **target repo**, not the skill directory, so the skill-relative `references/docs/shared-agent-conventions.md` that all eight shared agents cited resolved to nothing, and the rules it carries — prompt-injection boundary, read-only/full-access tool posture, the `gh --json` rule, the 0–100 confidence scale, autonomous operation, output discipline — silently never loaded into any of the 13 built agent prompts. `scripts/build.py` now splices six sections of `docs/shared-agent-conventions.md` **verbatim** into every emitted agent prompt (inside the `## Prompt` fence for the agents that have one, so the rules survive even when an orchestrator injects only the fence body), adding the confidence scale for `code-reviewer`/`ui-reviewer` only; the same preamble reaches the standalone `dist/agents/` and `.pi/agents/` outputs. The document stays the single source of truth — the six headings are matched exactly and a renamed, removed, or emptied section **aborts the build** rather than shipping a silently truncated preamble. Placement is guarded too, since a preamble emitted outside the injected fence would leave the rules unreachable while every heading-shaped assertion still passed: the build aborts when an agent declares `## Prompt` without a parsable opening fence, and when an inlined section body carries a ``` fence that would close the agent's prompt fence early. Logical references inside agent files now render as absolute repo URLs instead of skill-relative paths, so the `docs/agent-model-effort.md`, `docs/naming-conventions.md` and `docs/pre-commit-security.md` citations no longer dangle either, and the implementer's last skill-relative pointer resolves to the reproduction checklist its own prompt already spells out. Bundling is untouched: the transitive closure still scans the authored sources, so every skill ships exactly the docs it did before and every runtime *Bundled dependency precheck* list still resolves. @luongnv89
- **creator, triage:** add auto-mode carve-outs to the interactive gates (#244) — six confirmation gates had no defined non-interactive behavior, so autonomous runs could stall waiting for input that never arrives; the Normalize apply gate was a live deadlock for any orchestrator driving mid-loop normalization. The convention is now stated once in a new runtime doc `docs/auto-mode.md` — detection (`--auto` or `IDD_AUTO_MODE=1`, never caller provenance alone), the log-and-proceed gate rule, the `⚠` line format, and the safety stops auto mode must **not** weaken — and the gates cite it instead of restating detection per gate. In auto mode: the duplicate warning proceeds (naming the suspect), the create preview and batch approval auto-approve (batch logs the count and takes `[A]ll`, never `[e]dit`/`[c]ancel`), normalization auto-applies (never `dry-run`, and the mandatory backup still aborts on failure), issue-creator's mandatory pre-write repo sync aborts cleanly instead of asking, and issue-triage syncs without prompting. Interactive invocations are byte-for-byte unchanged — every gate still shows and still waits. Step summaries report `auto-approved` rather than claiming a human approved. The caller half is fixed too: `/auto-pilot` now states that every skill it delegates to — including the optional mid-loop `/issue-creator` normalization that made this a live deadlock — is invoked with `--auto` **and** `IDD_AUTO_MODE=1`, never relying on the callee detecting auto-pilot provenance, and it bundles `docs/auto-mode.md` so it can read the contract it is bound by. @luongnv89
- **auto-pilot:** continue the loop when a merge is dependency-blocked (#243) — the Phase 5.1b dependency gate (and the Phase 3-4 partial-merge path) still **never** merges out of `Depends on #N` / `Blocked by #N` order, but a blocked PR no longer ends the run: the iteration records `blocked_by_dependency`, the PR is left open and unchanged, the issue joins the session skip list (so the continuing loop cannot re-pick it and write a second run-log line), and the loop advances to the next eligible issue. A 30-issue backlog with one blocked PR now resolves the other 29 instead of halting at iteration 3. Dependency-blocking is no longer a stop-and-ask autonomy exception — critical-issue review failure is the only one left — and the loop stops on dependency grounds only through the existing `⚠ No eligible issues to pick` condition. SPEC §2 merge-order semantics are unchanged. @luongnv89
